# Mandatory development protocol / دستورالعمل توسعه
Read PROJECT_STATE.md, VERSION.json, CHANGELOG.md and docs before editing. For every logical change record date, version, purpose, affected paths, implementation, decisions, test evidence, failures, limitations, rollback and next step. Update PROJECT_STATE.md and DEVELOPMENT_LOG.md and CHANGELOG.md in the same change set; update architecture/API/install docs and VERSION.json when applicable. Verify commits and report exact links. Never label planned or untested work complete. Preserve existing functionality; use feature branch and PR, no main merge without approval. Never commit credentials, connection keys, private MPP data, proprietary dependencies or raw sensitive logs. Keep sanitized evidence and references. Markdown in clear Persian or English; identifiers and JSON in English. If documentation write fails, report incomplete change and repair before proceeding. This policy applies to all future work in this module.

For each release or source milestone update main msp-bi/plugin-about.json as the shared About metadata feed (sourceVersion/history; publishedVersion only after verified release). Keep desktop and dashboard fallback contacts aligned; do not use About metadata as update authorization. Record verification of both surfaces.
